# Open Outcry Public Brand Book

**Direction: Pit & Ledger.** An editorial broadcast from a real market floor, interrupted by machine receipts and bound by one live Tape.

## Audience

The public brand book serves three readers:

1. Ayaz, deciding whether a visual surface belongs to Open Outcry.
2. An implementation agent or developer looking for the reusable contract and its composition rules.
3. A visitor encountering the identity for the first time.

## Primary understanding

Within one screen, a visitor must be able to reconstruct this sentence: **Open Outcry is a design language where human judgment speaks in Broadcast, machine evidence answers in Console, and the Tape keeps both attached to live state.**

## Primary action

Inspect the rules, then open or copy the stable source files: `tokens.css`, `components.css`, and `DESIGN.md`, or inspect the repository source.

## Secondary actions

- Navigate directly to an act or component family.
- Compare correct and incorrect register use.
- Inspect component states and responsive behavior.
- Read source and provenance receipts.

## Success test

A new reader must be able to answer these questions without explanation:

1. When do I use Broadcast?
2. When do I use Console?
3. What role does the Tape play?
4. What must never be mixed on one plate?
5. Where is the stable implementation contract?

## Content boundary

Vault access informs subject matter and operating posture; it never grants permission to publish biography, operations, or private source material. The public brand book must never expose:

- age, family, locations, deadlines, finances, account values, job status, or health state;
- private task names, vault paths, hostnames, credentials, or live service data;
- unapproved extracts from personal notes.

Specimen content may borrow structures such as market state, an agent receipt, service status, or an archive source, but the values must be fictionalized or owned by the design system. The only real numbers on the page are artifact-owned facts: token count, component inventory, contract version, source files, public provenance, and verification state.

## Name provenance

The name was machine-suggested by Fable and operator-ratified by use. That provenance belongs in the closing receipt as `NAME / MACHINE-SUGGESTED BY FABLE / OPERATOR-RATIFIED BY USE`; it is never the hero narrative. The public artifact must not invent an origin story.

## Non-goals

This reconstruction does not roll Open Outcry across the vault, redesign the Command Room, or change the stable contract version. It adds no mascot, character, generated historical figure, provider integration, CMS, framework, component package, theme builder, or tweak panel. It publishes no live personal market, account, task, or service data; introduces no new colour palette or font family; and keeps no preservation copy of the former `index.html` because Git history is the archive.
