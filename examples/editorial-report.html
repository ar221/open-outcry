Research note / document provenance

A published note should carry its own receipt.

A live lookup keeps a dashboard useful. The same lookup can change the evidence beneath a dated argument. Choose the source’s behavior to match the document’s job.

An illustrative decision, not a repository policy. The observations below come from public Open Outcry files; the recommendation is an editorial judgment based on those observations.

00

The decision

For a published research note, freeze the provenance at publication, give each fact one owner in the source, and issue a newly dated edition when the argument changes. Keep older editions available. This preserves the relationship between what an author saw and what they concluded.

This rule does not apply to dashboards, status surfaces or the living brand book. Their reader is asking what is true now. A stale snapshot would frustrate that purpose.

01

Two questions, two sources

“What is the current value?” and “What supported this conclusion?” can require different answers. If a note fetches a new value every time it opens, its paragraph may remain unchanged while its apparent evidence moves. The reader can no longer tell which value the author used.

Freezing the receipt makes that relationship inspectable. It does not make the claim correct or the citation permanent. A source URL can move, and a captured value can be wrong. The author still needs to name the source and observation date; important external evidence may need an archived copy or a version-pinned reference.

A separate problem is duplication. Two handwritten copies of a version label can disagree even in a wholly static page. Whether the source is frozen or live, repeated appearances should derive from one owner. Choosing a publication model is not a substitute for choosing that owner.

02

What this repository shows

01 / A version label can have one owner

The brand book’s script reads the visible contract labels and mirrors them into other version nodes and the crawl. Its version-mirror comment records why: separately typed labels had drifted apart. The current mechanism repairs duplication; it does not independently establish that the owning label matches a stylesheet release.

brandbook.js, version mirror; opening contract block.

02 / Live resolution can be the right choice

The token ledger reads the loaded stylesheet rather than maintaining a second typed table. That behavior belongs in a living reference: the values being demonstrated are the values the page actually uses. It illustrates why this report excludes current-state surfaces from its recommendation.

Token ledger; brandbook.js, stylesheet inspection.

03 / A passing check has a limited claim

The contract verifier checks that display-declaring component classes carry a hidden-state guard. It does not check provenance, factual accuracy or every accessibility requirement. A receipt should name what a check establishes rather than turning a narrow pass into a general quality claim.

verify-contract.mjs; contract workflow.

03

Staleness becomes explicit

A frozen receipt ages by design. Make its date easy to find, avoid live-status decoration, and separate later corrections from the original edition. This is editorial work: an author must preserve old copies and explain why a new one exists.

The benefit is portability. The note can retain its own evidence summary without an endpoint, permission prompt or network request. External citations still require access; the receipt is not an archive of every linked source.

04

What was rejected

Live lookup
Right for a current-state mirror. Rejected for a dated note because the evidence can change without the argument changing.
Frozen + live badge
Potentially useful for an explicit comparison. Rejected here because the note does not need two competing values or another runtime dependency.
No receipt
Less authoring work, but removes the reader’s direct route from the conclusion to its supporting sources.
Chosen
Frozen receipt, one owner, new edition on change. Accept the maintenance cost and label the date.
05

Preserve the argument’s context

A published note should let a later reader reconstruct the author’s reasoning. Freeze what supported the claim, identify its source and date, and do not silently replace it with today’s answer. Use live resolution where today’s answer is the product.
